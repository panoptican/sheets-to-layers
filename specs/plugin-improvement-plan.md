**Behavior decisions to carry into implementation**

1. **Document-owned sync configuration.** Store a versioned configuration on the Figma document: validated source URL/spreadsheet identity, default worksheet identity, scope, stable target roots, and interpretation preferences. A page scope records that page's ID, so re-sync does not move to whichever page is currently open. A document scope covers the document's pages; selection scope stores ordered selected roots after removing duplicates and descendants of another selected root. Persist roots, not the subset of leaves that changed. Keep raw worksheet contents in the transient UI snapshot, not document metadata. One last-used configuration per document is sufficient for this work; a multi-source configuration manager is not required.

2. **Conservative legacy migration.** Existing global client storage cannot establish which file owns its URL or layer IDs. Use the legacy URL only as an input suggestion. The next explicit sync creates document metadata; re-sync without trustworthy metadata opens the normal UI. Missing saved roots produce a warning and retain the original intended scope for review; never widen to a full page automatically. If all roots are missing, require a new explicit scope selection. A completed partial run retains the full intended roots for retry; cancellation does not replace the previously completed configuration.

3. **One sync pipeline and stable row semantics.** All modes resolve roots → actual ancestor context → worksheets/bindings → preflight/repeat changes → current traversal → values/properties → images → terminal result. Row counters advance for every eligible binding, including unchanged or failed applications, in the same deterministic order. Missing labels are diagnosed; they do not silently change the meaning of another binding. Preserve documented specific, increment, skip-blank, and random modes. A random row is resolved once per run and reused by its preflight/application; a new run may randomize again. Retain an immutable in-memory application plan keyed by run/snapshot ID and binding identity, including worksheet, resolved row, and values. Retry failed applications against that same snapshot after revalidating the targets, rather than restarting counters over the failed subset. Refresh or reopening starts a full new run over saved roots; it does not pretend to resume a discarded snapshot.

4. **A shared binding grammar.** UI edits round-trip through a parser/serializer instead of regex suffix surgery. Simple existing names retain their meaning; a displayed `First Name` can serialize as `#First_Name`, with the index last. Quote/escape labels or worksheet names that cannot be represented unambiguously by the simple grammar, and document the extension. Diagnose normalization collisions rather than selecting the first header. Browsing preview tabs does not silently change document bindings; start on the URL's active tab and provide an explicit default-worksheet choice and “apply worksheet” action.

5. **Explicit interpretation and empty-data behavior.** Default a one-column sheet to header-plus-values. Preserve explicit Rows/Columns preferences per source worksheet and allow the preview to recompute from retained raw data without fetching again. Default blank text cells to the existing clear-and-hide behavior; offer “leave text unchanged” as a saved option. Blank image/component values leave existing content unchanged and are reported as skipped. Missing/invalid repeat data never triggers removal. For a valid zero-row source, preserve the template and existing structure with a clear “no data; repetition skipped” warning in this release, rather than deleting the only reusable template.

6. **Controlled structural and image edits.** Property-only variants resolve inside the current component set; explicit component names may change families only when unambiguous. Repeat removals are calculated before mutation and shown in preflight. Target the first existing image paint, replacing its hash while preserving paint properties and other fills; if no image paint exists, append one default image paint without deleting other paints. If a user changes/deletes a pending image target, treat the response as conflicted/skipped rather than overwriting the user's new paint.

7. **One cancellable operation through image completion.** Give each run an ID before fetching and correlate all data, progress, error, cancellation, preflight, and image messages. Main thread owns lifecycle and mutation authority; UI owns network AbortControllers. Terminal states are success, partial, failed, or cancelled, with changed/unchanged/skipped/failed counts and structured details. Only the active run can mutate or save metadata. Cancel during fetching means zero document changes; cancellation during application stops subsequent work and honestly reports changes already made. Do not promise automatic whole-document rollback. Re-sync closes only after images settle, and stays open when user action or failure details need attention.

8. **Practical UX and security defaults.** Fetch remains a read-only preview. Fetch & Sync may proceed automatically when preflight is unambiguous and makes no removals; otherwise show the concrete proposed changes and issues before Apply. Unsafe/ambiguous affected operations cannot proceed until resolved or explicitly excluded. Keep a visible summary for partial results. Finish the settings interface, persist its preferences, and disable third-party CORS fallback by default; an explicit opt-in identifies the provider and the data it receives. No credentials belong in the client bundle or public document metadata.

**Wave 2 — operation lifecycle, transport, and Worker hardening**

Owners: Sol and Terra/transport; Terra/interface wires lifecycle transitions. Luna extends fault fixtures where requested.

- Sol replaces loose pending flags with the agreed operation lifecycle, including cancellation before fetch, stale message rejection, preflight/apply identity, image queues/acknowledgements, and completion after image settlement. The UI disables conflicting starts; the main thread still rejects overlap and late messages independently. Retrying a failed subset must preserve source and resolved row choices.
- Terra/transport carries cancellation through both Worker and JSONP adapters. Remove script callbacks/listeners on cancellation, reject late callbacks safely, and bound fetch plus body consumption. Fresh Fetch/Re-sync must refresh values; shared in-flight requests may be deduplicated, while preview Sync deliberately uses its visible snapshot. Cache keys include source, worksheet, and interpretation; expose snapshot age and Refresh.
- Start with four concurrent image fetches and three concurrent worksheets, with at most six upstream requests in flight per plugin UI. Use a 15-second per-request deadline covering body reads, at most two retries for transient network/429/5xx failures, and a 90-second sheet-fetch deadline. Respect bounded Retry-After and cancellation. Benchmark/tune these named constants in Wave 4; avoid retrying permission/validation errors.
- Terra/transport quotes A1 references before encoding, validates spreadsheet IDs and URL hosts with a URL parser, and tests both values and formatting routes. Reject unsupported methods and protocols; validate redirect destinations, prevent obvious loopback/private/self-proxy targets, and verify what the hosting platform enforces rather than claiming a complete SSRF defense from a hostname regex. Validate image content and stream bytes with a proposed 20 MiB limit, including absent or false Content-Length. Confirm Figma-supported formats; unsupported formats get an actionable error. Bound sheet response/cell processing and show a clear limit error instead of silent truncation.
- Remove automatic third-party CORS fallback. Connect only the explicit opt-in path to settings, redact signed URLs from routine logs, and avoid logging credentials/upstream secret-bearing URLs. The intended image proxy remains public for validated public images under server-side limits; the Google API key is required only for Sheets operations. Arbitrary HTML/document responses are rejected. Document that client-side controls cannot protect a public proxy from outside callers. Sol reviews Worker validation, redirection, timeouts, and limits independently.

Exit gate: Cancel-before-fetch causes zero mutation/metadata writes; cancelling a new run preserves an existing completed configuration; cancellation during application/images stops subsequent mutations; late/duplicate/reversed messages cannot win; user-edited/deleted pending image targets are skipped visibly; partial worksheet/image failures remain visible; retry of a failed binding preserves its resolved row and successful neighbors; every terminal path settles and releases timers/listeners.
